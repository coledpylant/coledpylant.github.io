Steam Game Recommender

Built and compared four text-based recommendation approaches using Steam user reviews, moving from lexical matching to semantic embeddings and an intent-aware recommendation pipeline.

Project at a glance

PythonspaCyWord2VecVADERCosine SimilarityLLM Intent Parsing
Review corpus built from public Steam and SteamSpy endpoints, then cleaned and balanced to reduce template, duplicate, and low-information reviews.
Problem

Recommend games from what a user means, not just the words they type.

The project tested how different text representations change recommendations when a request contains both desired attributes and something the user explicitly wants to avoid.

Data

Collected review and game metadata through public Steam and SteamSpy endpoints. The workflow removed checklist-template reviews, very short or mostly non-text reviews, duplicates, and games with insufficient usable review text. Reviews were capped per game so highly popular titles did not dominate the corpus.

Why it was difficult

A Bag-of-Words model treats “grindy” as relevant whether the user wants grind or wants to avoid it. The project therefore became a comparison of increasingly semantic representations and, finally, explicit preference direction.

Approach

Four recommendation systems, one user request

Keeping the recommendation task fixed made it possible to compare what each representation added and where it failed.

1. Bag-of-Words

spaCy preprocessing, document-term vectors, cosine similarity, VADER sentiment, and game-level aggregation. It produced sensible open-world recommendations but mishandled negation.

2. Pretrained vectors

Replaced exact word overlap with semantic representations so related language such as “fight” and “combat” could contribute to similarity even without exact matches.

3. Custom Word2Vec

Trained 100-dimensional domain-specific embeddings directly on the Steam review corpus. The model learned useful gaming relationships around performance, combat, story, and exploration.

4. Intent-aware model

Used an LLM only to structure the user’s positive and negative preferences. Custom-vector retrieval and attribute-level evidence were then scored deterministically in Python.

Results

The representation changed the recommendation.

Each model surfaced different titles, showing that recommendation quality depends heavily on how user intent and review language are represented.

Intent-aware top three

Hollow Knight
Divinity: Original Sin 2 – Definitive Edition
Portal 2

The final model separately evaluated evidence for story/immersion, exploration, combat, and repetition/grind rather than relying on one overall similarity score.

Key lesson

Adding an LLM did not replace the recommender. Its useful role was narrower: interpreting the request and preserving preference direction. Similarity, evidence aggregation, and final ranking stayed in a reproducible pipeline.
